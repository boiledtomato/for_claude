How to upload a Decoy Connector VHD to Azure Blob Storage using AzCopy

Note:

Special thanks to

Raj Patil

for their contributions to this guide. If you require help with the implementation of your specific configuration, please contact our

Zscaler Deployment Services team for assistance

________________________________________________________________________________________

Introduction

You may run into problems when uploading the Decoy Connector .vhd file manually through the Azure portal. The upload can take a long time, it may fail partway through or result in a corrupted file. Using AzCopy provides a faster and more reliable way to upload the .vhd, reducing the risk of interruption or corruption.

Note:

The commands used below were executed on a Linux machine. The syntax and command format may differ when running it on a Windows machine (Command Prompt or PowerShell)

Solution

Step 1: Download the Decoy connector VHD ZIP

Go to Settings > Topology > Decoy Connector.

Click Download Image and select HyperV to download the image (.vhd.zip) file.

Download link for v5.0.3:

https://downloads.smokescreen.io/9d554545-c25e-4a0b-845a-f44bc710c77a/v5.0.3/appliance-v5.0.3.vhd.zip

(Always download the latest image from the Deception admin portal)

Step 2: Extract the ZIP files and check the VHD hash

Extract the zip file and grab the hashes. Use the following command:

md5sum appliance-v4.5.214.vhd

sha256sum appliance-v4.5.214.vhd

Step 3: Upload the VHD file to Azure Blob Storage

Upload the VHD file by the below command and have a look at the percentage:

az storage blob upload --account-name --account-key --file -c -n --content-md5

Example:

az storage blob upload --account-name zad1lotus --account-key 72020f3 --file appliance-v4.5.214.vhd -c decoy-connector-images -n Decoyconnector-v4.5.214 --content-md5 2cf8655a83ab6678e5e94d3472020f38

Step 4: Download the uploaded file and verify the hash

Download the uploaded file to verify that it's uploaded correctly.

Check the hash of the downloaded file using the following command and verify if it matches with Step 2 hashes.

md5sum appliance-v4.5.214.vhd

sha256sum appliance-v4.5.214.vhd

Once the file is successfully uploaded you can start configuring the Decoy connector image on Azure.

Reference links:

Deploy the Decoy Connector on Azure

Add and Connect the Decoy Connector to the Deception Admin Portal

Please reach out to us in the comments section if you have any questions.

Zscaler Deception Landmine Agent Safe Mode

Note:

Special thanks to

Raj Patil

for their contributions to this guide. If you require help with the implementation of your specific configuration, please contact our

Zscaler Deployment Services team for assistance

________________________________________________________________________________________

Understanding Safe Mode

Safe mode lets administrators remotely reduce an agent to its minimum operating state without uninstalling it. When safe mode is enabled, the agent continues only essential functions for connectivity and management.

It keeps heartbeats, diagnostic log uploads, and cleanup or uninstall procedures active, while pausing policy matching, decoy application deployment, identity threat detection and response (ITDR) scans, event generation, and other non-essential background services. This gives administrators a way to limit the agent’s operational footprint without removing it from the endpoint.

Triggering Safe Mode

Safe Mode can be activated or deactivated through the CMC console:

From the Agents Page:

A new option will be available on the agents' detail page to toggle Safe Mode.

Core Functionality - What Safe Mode Does

When an agent enters Safe Mode, it halts all non-essential operations, focusing only on critical functions required for basic connectivity and manageability.

Operations that remain ACTIVE in Safe Mode:

Heartbeats (to maintain connection with the management console)

Log uploads (if specifically triggered for diagnostics)

Cleanup and Uninstall procedures (to allow for agent removal if necessary)

Operations that are STOPPED/PAUSED in Safe Mode:

Policy matching

Decoy application/deployment

ITDR scans (e.g., threat detection activities)

Event generation

All other non-essential background services and activities.

Please reach out to us in the comments if you have any question.
