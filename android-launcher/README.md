# Herbarium — 19 世紀の手彩色植物図版のホーム画面

19 世紀の多色石版による植物図版を、そのままホーム画面にする Android ランチャー。

- 葉も花も**一枚ずつ別々に風に揺れる**。突風が左から右へ抜けていく
- **花や葉をタップすると蔦が這い出し**、蔦形の葉を開きながら伸びて、
  先についた**蕾がほどけて咲き**、中にアプリが現れる
- 1 か所に**複数のアプリ**を割り当てられる。蔦が枝分かれして同じ数だけ蕾をつける
- **蕾をタップすると花弁がほどけて開き**、アプリ一覧が咲き広がる

## 色と技法

色は Anne Pratt の多色石版（Pl.134, *Campanula*）から**実測**した値を使う
（`tools/flora/palette.py`）。記憶で選ぶと必ず彩度が上がりすぎる。実物の青は
くすんだスレートブルー、緑は黄みの強いサップグリーン、輪郭線は黒ではなく
暗い茶緑で、色数の少ない石版の渋さはそこにある。

技法は**淡彩であって、銅版画の線描ではない**。

- 細く確かな輪郭線を一本。線は輪郭と脈にしか使わない
- 内側は面で色を置く。濃淡も面で、同系色の濃い側を重ねて作る
- 脈は地より濃い同系色。花は裂片の先へ放射、葉は主脈から縁へ
- いちばん明るいところは紙の白をそのまま残す
- 葯の黄が一点入る。この黄がないと、青と緑だけでは図版に見えない

以前はハッチング（線の密度）で濃淡を作っていた。密度は出るが、線が増える
ほど図版の「軽さ」から離れていく。石版は色を塗って線を一本引いた絵である。

## 構成

```
android-launcher/
├── app/src/main/
│   ├── assets/flora/            # 版面の素材（tools/flora が生成。手で編集しない）
│   │   ├── manifest.json        #   茎の形、器官の付け根と揺れ、タップ判定
│   │   ├── organs/*.webp        #   葉と花を 1 つずつ焼いたもの
│   │   ├── bloom/*.webp         #   アプリ一覧を開く蕾の連続コマ
│   │   ├── vine/leafN.webp      #   蔦につく蔦形の葉
│   │   └── vine/bloomNN.webp    #   蔦の先の蕾がほどけて咲くまで
│   └── java/com/botanical/launcher/
│       ├── pencil/              # 鉛筆の線と幾何
│       │   ├── Stroke.kt        #   筆圧・ぶれ・紙の目。コマごとに引き直す
│       │   └── Geometry.kt      #   蔓、葉、花弁
│       ├── flora/               # 版面の読み込み
│       ├── data/                # アプリ一覧と割り当ての永続化
│       └── ui/
│           ├── FloraCanvas.kt   # 版面の描画
│           ├── Wind.kt          # 風
│           ├── Reach.kt         # アプリを開くときに伸びる蔦
│           ├── HomeScreen.kt    # 状態とタップ処理
│           └── AppDrawer.kt     # アプリ一覧
└── tools/flora/                 # 素材づくり（Python）
    ├── palette.py               #   図版から実測した色
    ├── pencil.py                #   線
    ├── leaves.py                #   葉の型（披針・広卵・羽状複葉・掌状）
    ├── shapes.py                #   釣鐘・正面向きの花・蕾・茎の筒
    ├── layout.py                #   配置。どこに何が生えるか（唯一の出どころ）
    ├── render.py                #   描き方。器官 1 つを描く手順（版面と共用）
    ├── plate.py                 #   版面を 1 枚絵に起こす
    ├── build_assets.py          #   器官を 1 つずつ焼いて manifest を書く
    ├── preview.py               #   端末に入れる前に動きを確かめる
    └── reach_preview.py         #   蔦が伸びて咲くまでを確かめる
```

## 導入

Releases から `Herbarium-*.apk` を落として開き、**設定 → アプリ → デフォルトのアプリ
→ ホームアプリ** で `Herbarium` を選ぶ。

## 操作

| 操作 | 動き |
|---|---|
| 花・葉をタップ | 蔦が伸びて花が開き、アプリが起動する。複数なら枝分かれして並ぶので選ぶ |
| 花・葉を長押し | その部位にアプリを割り当てる（複数選択可） |
| 蕾をタップ | 花弁がほどけて開き、アプリ一覧が咲き広がる |
| 紙の余白を長押し | アプリ名の表示、タップ範囲の可視化、割り当ての解除 |
| 戻る | 蔦を引っ込める／一覧を閉じる |

## なぜこの作りなのか

### 絵は描き起こしている

最初はスキャン画像を使っていたが、**1 枚の絵は歪ませることしかできない**。蕾が
ほどける、葉が茎から捻れる、といった動きは原理的に作れなかった。植物を部品から
組み立てて描くことにした。

### 形の作り方

いくつか、外すと一目で「植物画ではない」と分かる点がある。

**茎は筒として描く。** 太い線 1 本で引くと黒い棒になる。輪郭 2 本のあいだを
緑で埋め、影になる側の輪郭だけ太く濃くすると丸みが出る。

**釣鐘は「肩が丸く、胴が平行」。** 根元から口へ一直線に広げると円錐（ラッパ）に、
途中で最大にすると卵になる。手鈴と同じ形が条件。

**口の奥は、向こう側の縁と「歯をつける前の」手前の縁にはさまれた帯だけ。**
裂片の先まで奥に含めると、花が黒い泥に浸かったように見える。裂片の先は
こちらを向いた表面で、明るい。

**正面向きの花を混ぜる。** 参照図版でいちばん目を引くのはこの姿で、5 裂した
裂片・放射する脈・中央の黄色い葯がそろって初めてそう見える。

**蕾は「細い花弁が扇に開いたもの」ではない。** 5 枚がほぼ同じ向きに重なって
筒に巻きつき、全体が少しねじれている。付け根の角度を散らすと、どれだけ細く
しても「開いた花」にしか見えない。

**鋸歯と側脈の規則性を崩す。** 等間隔だと型抜きの飾り縁と魚の骨になる。

### 版面の解像度

構図は 1100x1800 の設計単位で書き、焼くときだけ `layout.SCALE` 倍する
（いまは 1.36 倍の 1496x2448）。版面は contain で画面に収まるので、1100 幅の
まま焼くと QHD（1440px 幅）の端末で 3 割ほど引き伸ばされ、石版の細い輪郭線が
最初に潰れる。小さい画面では `FloraLoader` が間引いて読む。

### 密度と動きの両立

淡彩は 1 枚の葉に何層も重ねるので、毎フレーム塗り直すには重すぎる。そこで

- **葉と花は 1 つずつ画像に焼き**、毎フレームは付け根を軸に回すだけにした
- **茎と伸びる蔦だけは線を直に引く**（形が毎フレーム変わるため）
- **蕾は 18 コマ焼いてある**。花弁は常に同じ枚数を描き、開き具合で角度と
  大きさとねじれを変える。閉じているときは深く重なるので外側の 1 枚の輪郭
  だけが見え、蕾になる

### 蔦（アプリを開くときに伸びるもの）

線を 1 本伸ばすだけでは蔦に見えない。参照図版の下半分にいる
**ツタバギキョウ（Campanula hederacea）** がそのまま手本で、

- 蔓はまっすぐ伸びず、左右にうねりながら進む（`Reach.waver`）
- **蔦形の葉が互い違いにつき**、先へ行くほど小さい
- 葉は蔓が通り過ぎてから、少し遅れて開く
- 先端の**蕾が見えたまま一拍おいてから**ほどける

最後の一拍（`REACH_HOLD_MS`）が要る。間を置かずに咲かせると、蕾があったことに
気づけない。伸び 720ms → 間 220ms → 開花 620ms。

### 描き直しは 11 コマ / 秒

線のゆらぎ（boiling line）は手描きアニメと同じで、滑らかにしすぎるとかえって
CG に見える。風の位相は滑らかに動かし、線の引き直しだけ 11 コマ / 秒に落として
いる。軽くもなる。

### 揺れの速さの倍率は整数

整数でないと位相が 1 周するたびに動きが飛ぶ。基準周期を 22 秒と長く取り、
遅いうねりと速い震えを同じ位相から作っている。

## 素材を作り直す

```bash
pip install pillow numpy scipy
cd android-launcher/tools/flora

# 構図を確かめる（1 枚絵）
python3 plate.py

# 器官を 1 つずつ焼いて manifest を書く
python3 build_assets.py

# 端末に入れる前に動きを確かめる
python3 preview.py --still --out still.png
python3 preview.py --seconds 6 --out motion.gif
python3 preview.py --seconds 5 --bloom --out bloom.gif

# 蔦が伸びて先の蕾が咲くまで（アプリを開く演出）
python3 reach_preview.py --apps 1 --out reach.gif
python3 reach_preview.py --apps 3 --out reach3.gif
```

`tools/flora/assets/` に出るので、`app/src/main/assets/flora/` へ丸ごと置き換えれば
反映される（古い器官が残らないよう、消してから入れ替える）。

構図は `layout.py` の `STEMS`（根元の位置、角度、丈、奥行、花数、葉数、葉の型）と
`ROOTS`・`CAPTION` で決まる。`plate.py`（版面）と `build_assets.py`（実機用の素材）は
どちらも `layout.build()` が返した配置だけを見て、器官は `render.py` の同じ関数で描く。
以前は同じ計算を両方に書き写していて、片方だけ直すと版面と実機で草の生え方がずれた。

### 触れる部位は少なく、大きく

タップ対象は葉が株ごとに 1 枚、花が全部、それと先端の蕾で 13 か所。判定の円は
`layout.separate()` が中心間距離の半分まで詰めるので、どこを押しても一意に決まる。
対象を増やすと一つひとつが小さくなり、複数アプリを登録したときに押し分けられない。

### 画面の文言は英語

図版が英国の植物誌なので、UI もそれに合わせて英語で通す。学名の
*Campanula latifolia* と並んだときに文字種が混ざらない。

### 画面下に固定する操作は navigationBarsPadding を付ける

割り当て画面の決定バーは、画面全体の Box に BottomCenter で置いている。
インセットを付けないとボタンがナビゲーションバー（ジェスチャーバー）の下に
潜り、押したつもりの操作がシステム側へ吸われる。逃げ道は取り消しの ✕ だけに
なるので、**「部位に留めたのに花が開かない」**という、原因から遠い形で表に出る。
一度これで踏んだ。

### 標本画であって、生け垣ではない

参照した19世紀の図版は、画面を葉で埋めていない。一株を根から花まで描き切り、
たっぷりの余白の中央に据え、下に学名を入れている。密度は「画面を埋めること」
ではなく「一株を完全に描き切ること」で出す。

## ビルドと配布

```bash
./gradlew assembleDebug
```

`android-launcher/` に変更を入れると CI が APK をビルドし、Actions の成果物として
90 日置く。Release を作るときは Actions から **Herbarium Launcher Build** を手動
実行し、`release_tag` にタグ名を渡す。

### 署名

`keystore/debug.keystore` をリポジトリに置き、debug ビルドはこれで署名する。
既定のデバッグ鍵はビルドする機械ごとに自動生成されるため、手元で作った APK と
CI が作った APK で署名が変わり、上書き更新が「アプリがインストールされていません」
で弾かれる。パスワードは Android のデバッグ鍵の慣例値で、秘匿する意味はない。
