# Pointille — 点描ランチャー

Android のホーム画面のアイコンを、すべて点描で描き直して統一するための個人用ホームアプリ。
参照はスーラ《グランド・ジャット島の日曜日の午後》。

`app/` の Kotlin は `prototype/index.html` の点描エンジンをそのまま移植したものです。

- `prototype/index.html` — ホーム画面。ブラウザで開くとそのまま触れます
- `prototype/motifs.html` — アイコンのモチーフ4案（B案採用）
- `prototype/touch.html` — 筆触の比較。B案のモチーフをスーラ／ゴッホで描き分け（**スーラ採用**）
- `prototype/unknown.html` — 手描きモチーフのないアプリをどう描くか（3段構えの検証）
- `app/` — Android Studio プロジェクト（Kotlin + Jetpack Compose）

---

## なぜ「ホームアプリ」なのか

Android には、他アプリのアイコンを横から差し替える仕組みがありません。純正ランチャーは
アイコンパックにも非対応です。配置も演出も自由にするなら、**自分がホームアプリになる**のが
唯一の道になります。

`android.intent.category.HOME` を持つ Activity をひとつ持つアプリを作り、端末の
「デフォルトのホームアプリ」に設定します。他アプリを改変するわけではないので root 化も
特別な権限も不要で、合わなければ設定から元のランチャーに戻すだけです。

## 点描にする処理

`prototype/index.html` の `paintPointillist`。絵の具を混ぜて中間色を作るのではなく、
**純色の点を並べて目の中で混ぜます**。

| | 処理 | 効果 |
|---|---|---|
| 1 | `dotColor` | 点ごとに元色から離れる。色相を振り、光は暖色へ、陰は寒色へ、まれに補色へ |
| 2 | `dab` | 一点は真円ではなく楕円のタッチ。縦横比1.0〜2.4、向きも輪郭のゆらぎも毎回変える |
| 2b | 運筆の向き | 一枚ごとに向きを決め、タッチの長軸をそこへ寄せる。格子は半ピッチずらして二度打つ |
| 3 | 図形の点群を分離 | 明度を保ち色味だけ乗せる。図形は明度で読ませる |
| 4 | `canvasPath` / `weave` | 張りキャンバス ── 麻の織り目、手で裁った縁、補色の点による縁取り |

**真円は禁物です。** 等間隔に真円を打つと、絵の具ではなく印刷の網点に見えます。スーラの
タッチ（tâche）は筆を一度置いただけの短い楕円で、向きも形も一つずつ違います。

**加減が全てでした。** 色を振りすぎると紙吹雪になり図形が沈みます。局所色をはっきり
主役に置き、アクセントは動かすためだけに使う。縁取りはグラン・ジャット島の額縁と同じで、
隣接する面の補色の点で描いています。

### たどり着くまでに捨てた2案

1. **フィルタ（ぼかし＋Kuwahara）** ── フィルタには「筆跡」の概念がなく、
   ぼやけたシールにしかならない。`app/` の Kotlin はまだこの方式
2. **筆致の構成的描画** ── 油絵にはなったが、輪郭に沿う筆で図形まで再構成すると
   80px でカメラがカメラに見えなくなった

## 筆が走る演出

`ui/BrushStroke.kt`。押した瞬間、絵の上を一本の筆跡が走ります。

一本の線ではなく11本の毛束として描き、毛ごとに色（絵から抜き出したもの）と不透明度を変え、
始点と終点で細くなる筆圧カーブを掛けています。数本は途中で紙から離れ、かすれになります。

`ui/HomeScreen.kt` の `LaunchWipe` が続きを受け持ちます。筆が走り終えてから画面が
そのアプリの色で塗り潰され、**塗り終わってから** `startActivity` を呼びます。順番が逆だと
演出が一切見えないまま新しいアプリが前面に出ます。

## 配置

`data/Salon.kt`。等間隔の格子ではなく、大小の絵を余白ごと構成するサロン掛けです。
`Salon.WALL` の11スロットと `Salon.DOCK` の4スロットが初稿の構図そのままの座標を持ちます。
どのアプリがどのスロットに掛かるかは `LayoutStore` が SharedPreferences に保存します。

## Android 実装

```
app/src/main/java/com/pointille/launcher/
├── MainActivity.kt          ホームアプリの入口。Back を握り潰す
├── paint/
│   ├── Pointillist.kt       点描エンジン。dab / dotColor / キャンバスのパネル
│   ├── Pen.kt               100x100 空間の描画ヘルパ
│   ├── Motifs.kt            島の日曜日のモチーフ15個と、パッケージ名の対応
│   └── IconSource.kt        3段構えの解決とディスクキャッシュ
├── data/
│   ├── AppRepository.kt     インストール済みアプリの列挙と実アイコン取得
│   └── Salon.kt             サロン掛けのスロットと配置の保存
└── ui/
    ├── HomeScreen.kt        壁・パレット・ドロワー・起動時の塗り潰し
    └── BrushStroke.kt       触れると走る筆跡
```

### 検証状況

この環境に Android SDK は無いので Gradle ビルドは通せませんが、`android.jar`
(API 35)、kotlinx-coroutines、Compose 1.7.6 / material3 1.3.1 /
activity-compose 1.9.3 を実際に取得して kotlinc 2.0.21 で型検査してあります。

| | 状態 |
|---|---|
| `paint/` `data/` | **完全にコンパイル成功**（フロントエンド＋コード生成） |
| `ui/` `MainActivity.kt` | **型検査は成功**。Composable のコード生成のみ、この環境では Compose コンパイラプラグインを登録できず未実行 |

この検査で実際に2件のバグを潰しました。

1. `0x80000000` 以上の16進リテラルは Kotlin では `Long` になる。ARGB 色の
   6箇所が `Int` として通らず、`.toInt()` が必要だった
2. パネルの切り抜きを `DST_IN` でやっていた。Skia はパスの被覆範囲内でしか
   合成しないので、**外側が消えず正方形のまま残る**。マスクを先に塗って
   `SRC_IN` で中身を載せる順に直した（プロトタイプでも同じ罠を踏んだ箇所）

### ビルド

```bash
cd android-icon-app
./gradlew :app:installDebug      # ラッパー同梱。Gradle 8.11.1 を自動取得します
```

Android Studio で `android-icon-app/` を開いても構いません。

インストール後、**設定 → アプリ → デフォルトのアプリ → ホームアプリ** で Pointille を選択します。

### 操作

| | |
|---|---|
| 絵をタップ | 筆が走ってからアプリが開く |
| 絵を長押し | 掛け替え／描き方の変更 |
| 壁を上にスワイプ | 全アプリのドロワー |
| Back | ドロワーを閉じる、掛け替えを取り消す |

描き方は **自動 → アイコンを点描に → 色面だけ → 手描きのモチーフ** の順に巡回します。
段ごとに別々にキャッシュするので、戻すのは一瞬です。

## この案件で踏んだ罠（再発しやすい順）

作り直しの原因になったものを、次に触る人のために全部残しておきます。

### 1. マスクの合成順 — **2回踏んだ**

パネルをキャンバス形に切り抜くのに `destination-in` / `DST_IN` を使うと、
**パスの外側が消えません**。Skia も Canvas2D も、合成はパスの被覆範囲内でしか
行わないためです。正しい順は「マスクを先に塗り、`SRC_IN` で中身を載せる」。

プロトタイプで直したのに、Kotlin 移植でまったく同じ書き方をして再発しました。
`Pointillist.cutCanvas` のコメントに理由を書いてあります。

### 2. 78px で沈むもの

小さいアイコンで潰れる原因は毎回この2つだけでした。

- **細い線** — 髭、蛇腹の折り目、細管。太くするか捨てる
- **地に近い明度** — 木の箱を緑の地に、暗い双眼鏡を暗い地に。地の色を変える

カメラ・音楽・ブラウザ・コルネット・暗箱カメラが、これで一度ずつ描き直しに
なっています。**描く前に地との明度差を決める。**

### 3. フィルタでは絵にならない

ぼかしや Kuwahara には「筆跡」という概念がありません。元画像をぼかすだけなので、
どうチューニングしても「ぼやけたシール」にしかならない。絵にするには**構成的に
描く**（一筆ずつ／一点ずつ置く）しかありませんでした。

### 4. 加減を外すと全部壊れる

- 色相を ±30度 振ったら紙吹雪になり、図形が沈んだ → 局所色を62%まで戻した
- 筆致で図形まで再構成したら 80px でカメラがカメラに見えなくなった → 地と図形を
  別レイヤーに分け、図形は輪郭を保つようにした
- 真円を等間隔に打つと印刷の網点に見えた → 楕円にして、運筆方向へ長軸を寄せた

**地は自由に、図形は忠実に。** これが一貫した解でした。

### 5. Kotlin の16進リテラル

`0x80000000` 以上は `Long` になります。ARGB 色を `Int` の引数に渡すと通りません。
`.toInt()` が要ります。ARGB を書くときは常に付けるのが安全です。

### 6. canvas は置換要素

CSS で `position:absolute; inset:0` だけでは、`<canvas>` は**固有サイズ 300x150 の
まま**です。`width:100%; height:100%` を明記しないと、塗り潰しが画面の一部しか
覆いません（プロトタイプの起動演出がこれで半分しか塗れていませんでした）。

### 7. 演出と起動の順番

筆が走る → 画面を塗り潰す → **塗り終わってから** `startActivity`。
逆順だと新しいアプリが即座に前面へ出て、演出が一切見えません。
